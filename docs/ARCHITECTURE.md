# TrailSafe architecture

TrailSafe stores hiking preparation data on the device and bundles guides, fonts and local calculations. It has no backend or monitoring service. Calls/messages are user-controlled system handoffs; forecasts and external resources require connectivity.

Five bottom tabs expose Plan (backpack), Prepare (clipboard checklist), Help, Guide and Tools. The title bar places a Home button to the left of the title and Info/About on the right, with 44-point touch targets and the same unsaved-edit guard as other navigation. The existing Home page remains at `/` and prominently exposes current and all trip plans. Plan groups Current, Upcoming and Past without changing saved status; Prepare focuses on checklists and gear. Emergency, guide search, article and trip-action deep links are preserved.

The store serializes writes under `trailsafe.local.v1`. Invalid existing data is preserved and blocks overwrites. Trip commands execute against the latest snapshot inside the queue and resolve after storage succeeds. Completed-plan editing saves authored values while preserving status. UI saving, sharing and exporting use an explicitly saved plan; incomplete drafts can be saved separately. Native date/time controls and Today/Tomorrow/Now shortcuts use the trip's editable IANA time zone. Now rounds the instant and updates its calendar date as well as its time; skipped or repeated DST wall times are rejected. Plan and profile editors share Router 58 removal protection plus the app navigation guard, covering browser/OS Back, tabs and document unload. A durable save clears protection before route replacement. Switching between the plan editor and preview remounts the screen so each opens at the top.

Local check-in reminders are an optional device convenience. A pure reconciliation function compares future reminders from persisted plans with scheduled TrailSafe notifications. It retains valid reminders, removes obsolete ones and creates missing ones. Permission denial/scheduling failure is visible independently of saving. Delete, complete, demote and reset paths use the same store boundary. Reminder opt-in does not affect overdue status.

Location watches run only for focused emergency/incident/Daylight/Compass GPS surfaces and while the application is foregrounded. Last-known positions retain timestamps and accuracy. Tools requires a fix or an explicit preset; it never silently chooses a place. The offline solar model supplies horizon/twilight estimates and selectable headlamp planning buffers; those buffers do not measure actual forest light. WMM declination uses magnetic-east-of-true sign wording. Hiking time is an estimate with distance/elevation/pace/pack allowances and requires no location permission or GPS watcher. An empty packing checklist binds to the latest Current trip on its first check; older nonempty progress keeps its original association until cleared.

Water guidance tells users to follow actual product instructions and use the built-in Clock timer. Cold illness guidance uses observable signs and actions rather than numerical risk scores. Signaling guidance recommends physical equipment. Audio/beacon and avalanche classification tools have been removed.

There is no content governance subsystem. Review bundled content directly in the app before release. Ordinary source links and a payload hash support reader attribution and optional device indexing. Region definitions are simple bundled data. Android indexing respects dynamic shortcut capacity; failed indexing does not mark content current.

Bugsnag is explicitly channel-gated. EAS profiles select development, preview, TestFlight or production. Production and web disable initialization. OTA updates are checked only on a user's explicit request; normal launch does not request an update. A new native artifact is required for native dependency changes.

Help Text 911 directly opens an editable system composer for the caller location; a separate someone-elsewhere draft omits reporter GPS. Tests inject inert emergency handlers. Browser tests intercept phone/SMS browser APIs, including the one-tap handoff; they never send messages. Native smoke tests never tap transports. Build/export evidence is separate from physical-device acceptance.

SDK 58 / Router 58 uses React 19.3 and React Native 0.88.0. Static HTML includes the new server document head/body nodes. Web async routes are explicitly disabled so loaded route navigation remains offline. Native scene startup is supplied by Expo; TrailSafe extends it only for Spotlight cold/warm links. Native crash initialization is generated only for pre-release channels. Local build scripts reject a native/JS channel mismatch.

Tools exposes Daylight, Compass and Hiking selectors at the top. Headlamp time precedes location/date settings; location presets expand only on request. Hiking duration precedes native distance/gain sliders and quick choices. Native sliders and accessible web ranges share the same estimate state.

Native diagnostic mods remove their previous generated blocks before selecting a channel, including legacy blocks without an end marker. Switching a reused preview project to production removes initialization; switching between permitted channels refreshes the stage. Incomplete blocks or unrecognized production initializers fail prebuild for inspection. Final store-artifact transmission remains a separate acceptance check.
